# dsh-agent-soul

> 给 DSH 的 agent 一份**会忘事的记忆**和一套**会变的人格**。

它做五件事：

| | 解决什么 |
|---|---|
| **人格** | 用 Markdown 写「你是谁」。项目人格只覆盖同名小节，全局的交待照常生效 —— 不会因为某个目录里有 `AGENT.md`，你在全局写的话就整份失效 |
| **记忆** | 值得记的事自己进来，随时间变模糊：清晰 → 清楚 → 模糊 → 只剩印象 → 遗忘。忘了不是删掉，是**先变得说不清** |
| **目的** | 从记忆里长出一份「心里惦记的事」，让她的主动有连续性 —— 不是定时问候，是主动想起 |
| **心情** | 每轮对话结束后自己判一次心情起伏（心情值 + 七情 + 时间线），**不注入提示词** —— 她不会被自己的情绪牵着说话，你也不用为情绪多付 token。但记下来的情绪有两个出口：喂给日记当底色、推着目的机制的驱动 |
| **日记** | 每天晚上到点，把当天的对话沉淀成两篇日记：一篇**公开**（可以拿给你看），一篇**私密**（只写给自己）。靠对话流水积累 + 摘要压缩，她自己用文件工具写 |

不管 B站、不管 QQ、不管桌宠。这个插件只关心「她是谁」和「她记得什么」。

---

## 从 dsh-agent-md 迁移

人格文件的**路径完全一致**，装上就能用，不用搬家：

```
<DSH_HOME>/AGENT.md                        全局人格（它已经在这写了）
<DSH_HOME>/agents/projects/<slug>.md       项目人格（同 slug 规则，同一目录算出同一个 slug）
```

所以你现有的两份人格文件会被直接认领，一个字都不用改。

**行为上有一处关键差异**（也是这个插件存在的主要理由）：它的人格是互斥的，我的是按小节叠加的 —— 详见下面的[人格注入区别](#人格注入和-dsh-agent-md-的区别)。

卸载 `dsh-agent-md` 时注意它 README 里写的两步都要做（`dependencies` 和 `dsh.profile.bundles` 各删一行），否则下次启动会因为「声明了却装不起来」卡住。

## 日常怎么用

装好之后基本**不需要操作**，它自己会跑。想干预时有四个入口：

### 1. 什么都不做（大多数时候）

- 你说话，值得记的事自动进记忆卡（主人说的偏好、目标、约定、第一次、情绪强的）
- 每天第一次打开，它会把不重要的事降一格清晰度
- 她答应过的事、没弄明白的事，自动变成「心里惦记的事」

### 2. 设置 → 灵魂（七个标签）

| 标签 | 用来干什么 |
|---|---|
| **概览** | 一眼看「到底生效没有」：人格来源是哪几个文件、记忆多少条、容量几成、惦记几件事 |
| **人格** | 直接编辑全局 / 项目人格。存完下一个回合生效 |
| **记忆** | 搜、看每条的清晰度和重要度、固定（永不遗忘）、删、手动加一条 |
| **目的** | 四个驱动值的当前读数 + 惦记的事清单，可以「放下了」 |
| **心情** | 此刻心情值 + 七情读数 + 时间线；可重置、可手动跑一次平复 |
| **日记** | 自动写日记的开关与时间、公开/私密语气、手动触发（可带备注）、最近日记列表 |
| **设置** | 注入预算、叠加还是互斥、各项开关、立即整理一次 |

### 3. 直接跟她说话

记忆有两个工具，她自己会用，你也可以直接要求：

```
「记住：我下周一开始做蓝桥杯的题」
「你还记得我之前说过什么关于 STM32 的事吗」
「把那条关于数学建模的记忆忘掉」
「你最近在惦记什么」
```

工具是 `soul_memory`（write/recall/forget/pin/list）和 `soul_goal`（add/done/list）。

### 4. 直接改文件

全是纯文本，用任何编辑器都行：

```
~/.dsh/AGENT.md                 全局人格 —— 想改她的性子就改这里
~/.dsh/agents/memory/global.json 记忆卡 —— 可以手改，改完刷新页面就生效
```

## 人格注入：和 dsh-agent-md 的区别

**核心差异只有一条：找到项目人格时，全局那份是「消失」还是「补齐」。**

| | dsh-agent-md | dsh-agent-soul |
|---|---|---|
| 有项目人格时全局怎么办 | **整份不注入**（互斥） | **按小节叠加**：项目覆盖同名小节，全局其余保留 |
| 你在全局写的通用约定 | 某些工作区完全不遵守，像没读到 | 到处都生效，除非项目里显式覆盖了同名小节 |
| 想回到老行为 | — | 设置里把模式改成「互斥」 |

具体到你的文件。你全局 `AGENT.md` 有 7 个小节：

```
# 你是谁  # 语气与形态  # 与树树的关系  # 行事准则  # 边界  # 互动约定  # 工程约定
```

假设某个项目里只写了：

```markdown
# 工程约定
这个项目用 Vue 3 + Vite。
```

- **以前**：全局整份消失 → 「你是谁」「语气与形态」「边界」全丢了，那个工作区的她完全变成另一个人
- **现在**：只有「工程约定」被替换，另外 6 个小节原样继承

这正是「全局约定在某些工作区完全不生效、像没读到一样」那个老坑的正面修法。

另外两个附带差异：

1. **`{{xxx}}` 会被降级成 `{xxx}`**：DSH 把双花括号当模板变量，未注册的名字会让**整轮注入失败**。两个插件都做了兜底。
2. **注入留痕更细**：概览页直接列出「这次注入了哪几份文件」，不用去翻 `inject-log.jsonl`。

## 三层来源与优先级

| 层 | 文件 | 怎么改 |
|---|---|---|
| 1 | `<cwd>/AGENT.md` | 自己的编辑器（跟着仓库走，可提交进 git） |
| 2 | `~/.dsh/agents/projects/<slug>.md` | 设置 → 人格 → **项目人格（本机）** |
| 3 | `~/.dsh/AGENT.md` | 设置 → 人格 → **全局人格** |

**项目层只取 1、2 里优先级最高的那一份**（不是两份合并）——两份都写着 `# 你是谁` 时，模型会各听一半，最后谁也不像。

设置页的「人格」标签会把这个层级**画出来**：逐层标「存在 / 没有」、给全路径、给正在生效的那层打标，并且顶部写明当前会话的工作目录和项目标识。

> ⚠️ **最容易踩的一个坑**：如果 `<cwd>/AGENT.md` 存在，它会盖住设置页编辑的第 2 层。
> 你在设置页改了、保存了、提示"已保存"，但其实**没生效** —— 因为第 1 层压着它。
> 页面检测到这种情况会亮一个黄框，直接告诉你「要么改那个文件，要么删掉它」。
>
> 常见于：工作区根目录放了一份项目专属的 `AGENT.md`，同时又想在设置页编辑「项目人格」那一层。



```
清晰 ──→ 清楚 ──→ 模糊 ──→ 只剩印象 ──→ 遗忘
200字     130字    42字+    只剩标题     移出提示词
                  「记不清了」「好像有…」  进 archive.jsonl
```

关键不在阶梯，在**注入时的措辞**：模糊的记忆会写成
「……（细节记不清了）」，只剩印象的写成「好像有「xx」这件事…（想不起来了）」。
模型看到的是「我隐约记得」，而不是「查无此事」或者「细节完备但其实已经不可靠」。

四条规则：

- **一天只降一档**：所以是慢慢模糊，不是某天突然想不起来
- **重要的事降得慢**：普通记忆每天 -0.35 留存，和主人相关的只有 -0.12
- **永远不会忘的**：固定的，和「第一次」类的事
- **提起来会变清楚**：被再次提及就刷新时间、召回 +1，一天回升一档

入库前会脱敏（密钥/手机号/身份证/卡号/链接），太短的不记（「嗯」「好的」不占位置）。

## 记忆：什么会被记住

自动提取不是「说过就记」，而是先按重要度打分，过线（42）才入库：

| 你说的 | 大概分数 | 结果 |
|---|---|---|
| 「今晚吃牛肉丸子汤」「多穿了点衣服」 | 低于阈值 | **不记** —— 一次性日常，记下来只会占着卡 |
| 「我手上有一块 F103 开发板」 | 44 上下 | 记（主人说的话整体偏宽松） |
| 「我打算明年参加蓝桥杯」 | 50 上下 | 记 |
| 「我明天要把概率论刷完」 | 60 上下 | 记 |
| 「我目标是当嵌入式工程师」「我是烟台大学大二」 | 70 以上 | 记，且**额外写一份进全局卡** |

最后一类叫**长期事实**（目标 / 专业 / 习惯 / 身份），有两个特权：永不遗忘、换工作区也认得你。

> 判据在 2026-10-29 重调过。原来「主人私下说的」直接 +42，而阈值就是 42 ——
> 等于只要是主人说的、超过 8 个字就免检入库，结果卡里躺着的五条全是「晚饭吃了什么」，
> 和真正有用的画像只差 5 分，判据没有区分度。现在身份只给 36，
> 剩下的差距交给内容信号（是否长期事实 / 是否承诺 / 是否第一次 / 情绪浓度）。

判据是纯规则 + 数值，不调模型 —— 确定性比聪明重要。

入库前自动脱敏：密钥、令牌、手机号、身份证、卡号、链接、**QQ 号**都会换成占位符。

## 目的机制：「主动想起」而不是「主动发消息」

四个驱动维度，各有 0~1 的值，**8 小时落一半**：

| 维度 | 被什么推高 |
|---|---|
| 想弄明白 | 疑问句、看不懂的东西 |
| 在乎 | 累、难受、熬夜 |
| 想分享 | 有意思的发现、推荐 |
| 想搞懂 | 学会了、跑通了、踩坑了 |

再加上从记忆里长出来的「没闭合的事」（答应过的、没弄明白的、想试试的），
渲染成很短的一段注入（默认 ≤ 320 字，最多 3 条）。

里面明确写着「**这不是任务清单，不需要每轮都提**」——
决定权在她手里，这比硬塞一句「去问候主人」更像自主，也不容易变成复读。

### 心情会推着她惦记

驱动还有一路来源是**七情**（见心情一节）：担心 / 心疼 → `在乎` 涨，
开心 / 甜蜜 → `想分享` 涨，踏实反而让「想说点什么」轻轻松一点。

不是每轮往上加，而是让驱动**向情绪推出的目标靠拢**（每轮 15%）——
累加式写法几十轮后会把所有驱动顶到 1，等于没有状态。靠拢则天然有收敛点：
情绪在，驱动停在较高的地方；情绪平复了，目标回到基线，驱动跟着落下来。

### 说出去了才算完

渲染出去的目标会被记下来，下一轮看她**有没有真的说出口**（她的话里有没有出现
那件事的 3 字词组）：

- 说到了 → 驱动 ×0.45，真的放下了
- 一直没说到，超过 6 小时 → ×0.85，慢慢淡了
- 刚渲染完不到 1 分钟 → 什么都不做，她还没轮到说话

两条都只判一次，判完就移出列表 —— 否则每轮都 ×0.85，驱动会被反复压到底，
跟情绪牵引打架。

> 本地 DSH 没有推送渠道（你不打开就没有回合），所以「主动」只能是主动想起。
> 真正的主动发消息属于 QQ 那边的事，不在这里。

## 日记：把一天沉淀成公开 + 私密两篇

每天晚上（默认 22:00）到点，插件会**发两条消息给 agent**，让她自己用文件工具写两篇日记：

- **公开**：`~/.dsh/agents/diary/public/YYYY-MM-DD.md`，首行 `【公开】`，可以拿给你看
- **私密**：`~/.dsh/agents/diary/private/YYYY-MM-DD.md`，首行 `【私密】`，只写给自己

先投第一条（只说写公开日记，只带公开日记的历史），等她写完、公开文件落盘了，
才投第二条（这时候才带私密历史）。**为什么分两条**：写在一条里的话，私密历史就摆在
下面，她写公开那一步时已经看到了本不该给人看的内容，「公开只喂公开日记」等于没说。

「私密」**完全靠提示词措辞**——文件是明文，没有加密。任何能读 `~/.dsh` 的人都能打开。
设置页里的「最近日记」也只展示公开那一篇的内容，私密只显示「有/没有」。

### 日记里带着当天的情绪

除了对话摘要，触发消息还会附上一段**情绪底色**：心情从多少走到多少、七情峰值、
几段「当时她自己的想法」（取自心情时间线里用第一人称写下的记录）。

- 公开那篇给 3 条，措辞是「可以写进去，但这是会拿给对方看的版本」
- 私密那篇给 6 条，措辞是「这是你当时的真实想法，不用收着」

只给事实与素材，不给「你要写得开心一点」这类指令 —— 一旦让她照着情绪演，日记就假了。
关掉心情（`moodEnabled: false`）或把条数设成 0，就不带这一段。

七情在日记里也是**百分比口径**（满格 20，见下），并且多一行「已经淡下去的」：
峰值 65% 而现在只剩 10%，说明那股劲儿过去了 —— 这种时间感只有日记里才有。

> ⚠️ 七情的「满格」是 **20 不是 100**：判定单次上限 ±10，又被 90 分钟半衰期往回磨，
> 2026-10-29 实测一整天峰值只到 13。所以设置页和日记都把 20 当 100% 折算 ——
> 「踏实 65%」是很踏实，不是刚过一半。

### 一天的分界线不是 00:00

日记 `2026-10-29` 覆盖的是 **2026-10-28 22:00 ~ 2026-10-29 22:00** 的对话。
这是刻意的：晚上十点写的时候，「今天」在感受上还没结束。
心情时间线也按同一个窗口筛 —— 换工作区、跨天都跟对话对得上。

### 对话是怎么拿到的

不是到点才去翻会话（冷会话拿不到），而是**平时就攒**：

```
每轮对话（tick 注入时）
  └─ 扫描新增的 user/message + assistant/message
  └─ 追加到 ~/.dsh/agents/diary/conversations/YYYY-MM-DD.jsonl
```

过滤口径跟记忆提取一致：`runtime-context`、`time-context`、技能清单、审批通知这类
宿主注入的上下文一条都不进 JSONL。

助手那边只记**她说出口的话**：`reasoning`（思考过程）和工具调用都不进。
实测一个活跃会话里 90% 的助手消息是思考过程、只有 10% 是真正在说话，
全收的话日记会变成一堆英文内心独白，而且一天能攒到几十万字。

JSONL 默认保留 7 天，触发时顺手清理旧的（保留天数要 ≥ 补写能追溯的天数）。

到点触发时：

```
读 JSONL（按 22:00 分界裁剪两天文件）
  → 裁到上限（默认 30000 字，超出保留最近的部分）
  → LLM 摘要压缩（失败用原文截断兜底）
  → 读最近 4 天日记
  → 投第一条（公开）→ agent 写完 → 投第二条（私密）
```

### 启动补写

DSH 关机期间不会跑定时器。所以启动时会检查**今天之前最近该补的那一天**，两条门槛：

- **至少写过一篇日记** —— 补写是补断档，不是回溯历史。刚装上插件时不补，等当晚正常写第一篇
- **那天确实有对话** —— 没对话的日子补出来只能是空洞的意识流

只补最近的一天。更早的不补——一次补十篇只会让日记变成流水账。

### 手动触发

设置页「日记」页签里点「现在写日记」，可以选日期、加备注。或者直接调接口：

```bash
curl -X POST http://127.0.0.1:<PORT>/api/soul/diary \
  -H 'content-type: application/json' \
  -d '{"date":"2026-10-29","note":"今天发生了一些特别的事"}'
```


## 花钱的地方

**记忆和目的这两段是每回合重发的**，跟工具 schema 一样不进压缩，是常驻成本。

- 默认记忆预算 1600 字，实际约 **1100~1500 token**
  （DSH 按 4 字符/token 粗算，中文真实是它的 1.4~1.9 倍）
- 目的段默认 ≤ 320 字，约 **300~500 token**
- 人格正文你写多少就是多少

觉得贵：先砍 `injectMaxChars`，再考虑关「目的机制」。
用工具 schema 省下来的那点钱，别在这两段上花回去。

## 配置

`<DSH_HOME>/agents/persona.json`：

| 键 | 默认 | 说明 |
|---|---|---|
| `mode` | `stack` | `stack` 叠加 / `exclusive` 互斥 |
| `includeGlobal` | `true` | 全局人格是否参与注入 |
| `projectPersonaEnabled` | `true` | 是否启用项目人格 |
| `injectMaxChars` | `1600` | 记忆注入预算 |
| `memoryEnabled` | `true` | 是否注入记忆（关掉仍在后台记） |
| `projectMemoryEnabled` | `true` | 项目记忆独立一张卡 |
| `purposeEnabled` | `true` | 是否注入「心里惦记的事」 |
| `diaryEnabled` | `true` | 是否启用每日日记 |
| `diarySchedule` | `"22:00"` | 触发时间（HH:MM） |
| `diaryCatchUp` | `true` | 启动时补写最近缺失日 |
| `diaryBackfillDays` | `4` | 写新日记时参考前几天的旧日记 |
| `diaryOverwrite` | `true` | 同日重复触发是否覆盖 |
| `diaryManualNote` | `true` | 手动触发是否允许附备注 |
| `diaryPublicTone` | `""` | 公开日记语气（空 = 让模型自己把握） |
| `diaryPrivateTone` | `""` | 私密日记语气 |
| `diaryMaxConversationChars` | `30000` | 喂给摘要的对话上限（超了只留最近的部分） |
| `diaryMaxSummaryChars` | `2000` | 摘要最大字数 |
| `diaryPublicMoodMoments` | `3` | 公开日记里带几条「你当时的想法」（0 = 不带） |
| `diaryPrivateMoodMoments` | `6` | 私密日记里带几条 |
| `diarySummarizeProvider` | `""` | 摘要模型 provider（空 = 跟随会话模型） |
| `diarySummarizeModel` | `""` | 摘要模型名称 |
| `diaryJsonlKeepDays` | `7` | 对话 JSONL 保留天数（要 ≥ 补写能追溯的天数） |
| `diarySummarizeTimeoutMs` | `30000` | 摘要调用超时（毫秒） |

记忆引擎参数（衰减天数、阈值、压缩）在 `lib/memory.js` 的 `DEFAULTS`，
全部有注释说明为什么是这个值。

## 排障

```bash
grep "\[apply\]"  ~/.dsh/agents/soul.log | tail -3   # 三段注入有没有起来
grep "\[extract\]" ~/.dsh/agents/soul.log | tail -5  # 自动记忆记了几条
grep "\[memory\]" ~/.dsh/agents/soul.log | tail -5   # 衰减/压缩做了什么
grep "\[tool\]"   ~/.dsh/agents/soul.log | tail -5   # 工具注册成功没
grep "\[diary\]"  ~/.dsh/agents/soul.log | tail -10  # 日记：下次触发时间、摘要结果、投递成功没
```

**设置页「灵魂」不出现**：① 插件是不是真加载了（看 `[apply] 启动` 那行）
② 目录名 / `package.json` 的 name / `cordis.patch.yml` 的 name 三处是否完全一致
③ 重启 DSH —— 浏览器半侧是启动时装配的

**人格变了但没生效**：DSH 只在渲染文本**变化时**才重新追加这一段，
改完在下一个回合生效。设置页「概览」里能看到当前实际注入的是哪几份文件。

**记忆一直在掉条数**：`archive.jsonl` 里能查回来。觉得不该忘就
在设置页把它固定（固定后永不淘汰），或者把 `forgetAfterDays` 调大。

**日记到点没写**：① `grep "\[diary\]"` 看有没有「下次触发」那行
② 「没有可用会话」= 当时没有活着的会话且冷启动失败，手动点一次「现在写日记」
③ 「摘要失败」不算错 —— 会用原文截断兜底，日记照常写
④ 写出来的还是空的：看 agent 那一轮有没有真的调用文件工具，可以在「日记」页签手动触发放着看

**日记内容不像自己**：`diaryPublicTone` / `diaryPrivateTone` 留空时语气全靠模型自由发挥；
写两句具体的（「温暖但克制」「真实、不设防」）比写「好好写」有用得多。

## 开发

```bash
npm test              # 全量：先构建 client，再跑 提取 / 目的复活 / 记忆 / 日记 / 心情 / 人格 / 目的 / 登记 / 冒烟 / 浏览器半侧
npm run build:client  # 只把 lib/client/*.js 拼成 lib/client.js
npm run test:memory   # 只跑记忆引擎
npm run test:diary    # 只跑日记：时间分界 / 对话扫描 / 补写 / 触发消息 / 清理
npm run test:smoke    # 用假宿主跑一遍 apply()：注入段 + 工具 + API
npm run test:client   # 先构建，再用假 __ModuleLoader__ 跑一遍浏览器 bundle
```

单测只碰纯函数，用临时目录，不动真实的 `~/.dsh`。

### 浏览器半侧是拆开写的，`lib/client.js` 是生成物

DSH 客户端模块系统**一个包只出一个 bundle、兄弟文件无法同步 require**，所以浏览器
半侧不能真的拆成互相 `import` 的文件。这里的做法是：源码按职责放在 `lib/client/`：

```
lib/client/styles.js        样式（CSS + ensureStyles）
lib/client/api.js           同源 HTTP + cwd/时间工具
lib/client/components.js    共享小组件（Badge/Card/Dot/Pill/Switch/Kv）
lib/client/overview-tab.js  概览
lib/client/persona-tab.js   人格
lib/client/memory-tab.js    记忆
lib/client/purpose-tab.js   目的
lib/client/mood-tab.js      心情
lib/client/diary-tab.js     日记
lib/client/settings-tab.js  设置
lib/client/app.js           外壳（SoulSection/ErrorBoundary/apply/导出）
```

`tools/build-client.mjs` 按固定顺序把它们拼回**唯一入口 `lib/client.js`**。要改浏览器
半侧就改 `lib/client/` 里的片段，然后跑 `npm run build:client`（`npm test` 会自动先构建）。
每个片段都能单独 `node --check`，引用未定义变量只是运行时的事，不影响语法检查。

后两个测试是**装进 DSH 之前唯一的保险**，因为这两类错误 `node --check` 抓不到：

- `smoke`：`apply()` 在某个 ctx 服务上炸掉 → 插件加载了但注入没生效
- `client`：浏览器 bundle 里用到宿主没提供的全局（`module` / `exports`）→
  DSH 报 `1 entry did not activate` 直接起不来

两个都真实发生过，所以留下了。
