# dsh-agent-soul

> 给 DSH 的 agent 一份**会忘事的记忆**和一套**会变的人格**。

它做三件事：

| | 解决什么 |
|---|---|
| **人格** | 用 Markdown 写「你是谁」。项目人格只覆盖同名小节，全局的交待照常生效 —— 不会因为某个目录里有 `AGENT.md`，你在全局写的话就整份失效 |
| **记忆** | 值得记的事自己进来，随时间变模糊：清晰 → 清楚 → 模糊 → 只剩印象 → 遗忘。忘了不是删掉，是**先变得说不清** |
| **目的** | 从记忆里长出一份「心里惦记的事」，让她的主动有连续性 —— 不是定时问候，是主动想起 |

不管 B站、不管 QQ、不管桌宠。这个插件只关心「她是谁」和「她记得什么」。

---

## 从 dsh-agent-md 迁移

人格文件的**路径完全一致**，装上就能用，不用搬家：

```
<DSH_HOME>/AGENT.md                        全局人格（它已经在这写了）
<DSH_HOME>/agents/projects/<slug>.md       项目人格（同 slug 规则，同一目录算出同一个 slug）
```

所以你现有的两份人格文件会被直接认领，一个字都不用改。

**行为上有一处关键差异**（也是这个插件存在的主要理由）：它的人格是互斥的，我的是按小节叠加的 —— 详见下面的[人格注入区别](#人格注入和-dsh-agent-md-的区别)。

卸载 `dsh-agent-md` 时注意它 README 里写的两步都要做（`dependencies` 和 `dsh.profile.bundles` 各删一行），否则下次启动会因为「声明了却装不起来」卡住。

## 日常怎么用

装好之后基本**不需要操作**，它自己会跑。想干预时有四个入口：

### 1. 什么都不做（大多数时候）

- 你说话，值得记的事自动进记忆卡（主人说的偏好、目标、约定、第一次、情绪强的）
- 每天第一次打开，它会把不重要的事降一格清晰度
- 她答应过的事、没弄明白的事，自动变成「心里惦记的事」

### 2. 设置 → 灵魂（五个标签）

| 标签 | 用来干什么 |
|---|---|
| **概览** | 一眼看「到底生效没有」：人格来源是哪几个文件、记忆多少条、容量几成、惦记几件事 |
| **人格** | 直接编辑全局 / 项目人格。存完下一个回合生效 |
| **记忆** | 搜、看每条的清晰度和重要度、固定（永不遗忘）、删、手动加一条 |
| **目的** | 四个驱动值的当前读数 + 惦记的事清单，可以「放下了」 |
| **设置** | 注入预算、叠加还是互斥、各项开关、立即整理一次 |

### 3. 直接跟她说话

记忆有两个工具，她自己会用，你也可以直接要求：

```
「记住：我下周一开始做蓝桥杯的题」
「你还记得我之前说过什么关于 STM32 的事吗」
「把那条关于数学建模的记忆忘掉」
「你最近在惦记什么」
```

工具是 `soul_memory`（write/recall/forget/pin/list）和 `soul_goal`（add/done/list）。

### 4. 直接改文件

全是纯文本，用任何编辑器都行：

```
~/.dsh/AGENT.md                 全局人格 —— 想改她的性子就改这里
~/.dsh/agents/memory/global.json 记忆卡 —— 可以手改，改完刷新页面就生效
```

## 人格注入：和 dsh-agent-md 的区别

**核心差异只有一条：找到项目人格时，全局那份是「消失」还是「补齐」。**

| | dsh-agent-md | dsh-agent-soul |
|---|---|---|
| 有项目人格时全局怎么办 | **整份不注入**（互斥） | **按小节叠加**：项目覆盖同名小节，全局其余保留 |
| 你在全局写的通用约定 | 某些工作区完全不遵守，像没读到 | 到处都生效，除非项目里显式覆盖了同名小节 |
| 想回到老行为 | — | 设置里把模式改成「互斥」 |

具体到你的文件。你全局 `AGENT.md` 有 7 个小节：

```
# 你是谁  # 语气与形态  # 与树树的关系  # 行事准则  # 边界  # 互动约定  # 工程约定
```

假设某个项目里只写了：

```markdown
# 工程约定
这个项目用 Vue 3 + Vite。
```

- **以前**：全局整份消失 → 「你是谁」「语气与形态」「边界」全丢了，那个工作区的她完全变成另一个人
- **现在**：只有「工程约定」被替换，另外 6 个小节原样继承

这正是你问题库 [Q20](../../DSH%20workspace/DSH问题库/F-工具与人格注入.md) 记的那个坑的正面修法。

另外两个附带差异：

1. **`{{xxx}}` 会被降级成 `{xxx}`**：DSH 把双花括号当模板变量，未注册的名字会让**整轮注入失败**。两个插件都做了兜底。
2. **注入留痕更细**：概览页直接列出「这次注入了哪几份文件」，不用去翻 `inject-log.jsonl`。

## 三层来源与优先级

| 层 | 文件 | 怎么改 |
|---|---|---|
| 1 | `<cwd>/AGENT.md` | 自己的编辑器（跟着仓库走，可提交进 git） |
| 2 | `~/.dsh/agents/projects/<slug>.md` | 设置 → 人格 → **项目人格（本机）** |
| 3 | `~/.dsh/AGENT.md` | 设置 → 人格 → **全局人格** |

**项目层只取 1、2 里优先级最高的那一份**（不是两份合并）——两份都写着 `# 你是谁` 时，模型会各听一半，最后谁也不像。

设置页的「人格」标签会把这个层级**画出来**：逐层标「存在 / 没有」、给全路径、给正在生效的那层打标，并且顶部写明当前会话的工作目录和项目标识。

> ⚠️ **最容易踩的一个坑**：如果 `<cwd>/AGENT.md` 存在，它会盖住设置页编辑的第 2 层。
> 你在设置页改了、保存了、提示"已保存"，但其实**没生效** —— 因为第 1 层压着它。
> 页面检测到这种情况会亮一个黄框，直接告诉你「要么改那个文件，要么删掉它」。
>
> 实测你机器上 `D:\DSH workspace\work\AGENT.md` 就属于这种情况。



```
清晰 ──→ 清楚 ──→ 模糊 ──→ 只剩印象 ──→ 遗忘
200字     130字    42字+    只剩标题     移出提示词
                  「记不清了」「好像有…」  进 archive.jsonl
```

关键不在阶梯，在**注入时的措辞**：模糊的记忆会写成
「……（细节记不清了）」，只剩印象的写成「好像有「xx」这件事…（想不起来了）」。
模型看到的是「我隐约记得」，而不是「查无此事」或者「细节完备但其实已经不可靠」。

四条规则：

- **一天只降一档**：所以是慢慢模糊，不是某天突然想不起来
- **重要的事降得慢**：普通记忆每天 -0.35 留存，和主人相关的只有 -0.12
- **永远不会忘的**：固定的，和「第一次」类的事
- **提起来会变清楚**：被再次提及就刷新时间、召回 +1，一天回升一档

入库前会脱敏（密钥/手机号/身份证/卡号/链接），太短的不记（「嗯」「好的」不占位置）。

## 目的机制：「主动想起」而不是「主动发消息」

四个驱动维度，各有 0~1 的值，**8 小时落一半**：

| 维度 | 被什么推高 |
|---|---|
| 想弄明白 | 疑问句、看不懂的东西 |
| 在乎 | 累、难受、熬夜 |
| 想分享 | 有意思的发现、推荐 |
| 想搞懂 | 学会了、跑通了、踩坑了 |

再加上从记忆里长出来的「没闭合的事」（答应过的、没弄明白的、想试试的），
渲染成很短的一段注入（默认 ≤ 320 字，最多 3 条）。

里面明确写着「**这不是任务清单，不需要每轮都提**」——
决定权在她手里，这比硬塞一句「去问候主人」更像自主，也不容易变成复读。

> 本地 DSH 没有推送渠道（你不打开就没有回合），所以「主动」只能是主动想起。
> 真正的主动发消息属于 QQ 那边的事，不在这里。

## 安装

```bash
# 1) 取代码
git clone https://github.com/danshuyue/dsh-agent-soul.git "<DSH_HOME>/plugins/dsh-agent-soul"

# 2) 挂进 profile（本地 link）
#    <DSH_HOME>/profiles/desktop/package.json：
#      dependencies 加  "dsh-agent-soul": "link:../../plugins/dsh-agent-soul"
#      dsh.profile.bundles 加  "dsh-agent-soul"
# 3) 建 junction（Windows）
mklink /J "<DSH_HOME>\profiles\desktop\node_modules\dsh-agent-soul" "<DSH_HOME>\plugins\dsh-agent-soul"

# 4) 重启 DSH → 设置 → 灵魂
```

装好之后：设置里出现「灵魂」，侧栏能看到概览、人格、记忆、目的、设置五个标签。

## 花钱的地方

**记忆和目的这两段是每回合重发的**，跟工具 schema 一样不进压缩，是常驻成本。

- 默认记忆预算 1600 字，实际约 **1100~1500 token**
  （DSH 按 4 字符/token 粗算，中文真实是它的 1.4~1.9 倍）
- 目的段默认 ≤ 320 字，约 **300~500 token**
- 人格正文你写多少就是多少

觉得贵：先砍 `injectMaxChars`，再考虑关「目的机制」。
用工具 schema 省下来的那点钱，别在这两段上花回去。

## 配置

`<DSH_HOME>/agents/persona.json`：

| 键 | 默认 | 说明 |
|---|---|---|
| `mode` | `stack` | `stack` 叠加 / `exclusive` 互斥 |
| `includeGlobal` | `true` | 全局人格是否参与注入 |
| `projectPersonaEnabled` | `true` | 是否启用项目人格 |
| `injectMaxChars` | `1600` | 记忆注入预算 |
| `memoryEnabled` | `true` | 是否注入记忆（关掉仍在后台记） |
| `projectMemoryEnabled` | `true` | 项目记忆独立一张卡 |
| `purposeEnabled` | `true` | 是否注入「心里惦记的事」 |

记忆引擎参数（衰减天数、阈值、压缩）在 `lib/memory.js` 的 `DEFAULTS`，
全部有注释说明为什么是这个值。

## 数据在哪

```
<DSH_HOME>/AGENT.md                              全局人格
<DSH_HOME>/agents/projects/<slug>.md             项目人格
<DSH_HOME>/agents/persona.json                   配置
<DSH_HOME>/agents/memory/global.json             全局记忆卡
<DSH_HOME>/agents/memory/projects/<slug>.json    项目记忆卡
<DSH_HOME>/agents/memory/purpose.json            目的状态
<DSH_HOME>/agents/memory/archive.jsonl           遗忘档案（append-only）
<DSH_HOME>/agents/soul.log                       日志（2MB 轮转）
```

全是纯文件，没有数据库。备份就是复制目录，恢复就是复制回来。

## 排障

```bash
grep "\[apply\]"  ~/.dsh/agents/soul.log | tail -3   # 三段注入有没有起来
grep "\[extract\]" ~/.dsh/agents/soul.log | tail -5  # 自动记忆记了几条
grep "\[memory\]" ~/.dsh/agents/soul.log | tail -5   # 衰减/压缩做了什么
grep "\[tool\]"   ~/.dsh/agents/soul.log | tail -5   # 工具注册成功没
```

**设置页「灵魂」不出现**：① 插件是不是真加载了（看 `[apply] 启动` 那行）
② 目录名 / `package.json` 的 name / `cordis.patch.yml` 的 name 三处是否完全一致
③ 重启 DSH —— 浏览器半侧是启动时装配的

**人格变了但没生效**：DSH 只在渲染文本**变化时**才重新追加这一段，
改完在下一个回合生效。设置页「概览」里能看到当前实际注入的是哪几份文件。

**记忆一直在掉条数**：`archive.jsonl` 里能查回来。觉得不该忘就
在设置页把它固定（固定后永不淘汰），或者把 `forgetAfterDays` 调大。

## 开发

```bash
npm test              # 210 条断言：记忆 65 / 人格 35 / 目的 48 / 主进程冒烟 41 / 浏览器半侧 21
npm run test:memory   # 只跑记忆引擎
npm run test:smoke    # 用假宿主跑一遍 apply()：注入段 + 工具 + API
npm run test:client   # 用假 __ModuleLoader__ 跑一遍浏览器 bundle
```

单测只碰纯函数，用临时目录，不动真实的 `~/.dsh`。

后两个测试是**装进 DSH 之前唯一的保险**，因为这两类错误 `node --check` 抓不到：

- `smoke`：`apply()` 在某个 ctx 服务上炸掉 → 插件加载了但注入没生效
- `client`：浏览器 bundle 里用到宿主没提供的全局（`module` / `exports`）→
  DSH 报 `1 entry did not activate` 直接起不来

两个都真实发生过，所以留下了。
