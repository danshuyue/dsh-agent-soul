# 待做的三件事（2026-11-01 设计稿）

> 现状：灵魂插件已经有 人格注入 / 记忆（衰减、遗忘、压缩）/ 心情 / 目的 / 日记。
> 这三件是糖糖自己想要的，按"最便宜 → 最值钱"排了实现顺序：② 心情影响语气 → ① 联想召回 → ③ 日记连续线。

---

## ② 心情影响语气（最便宜，半天）

### 目标

心情低的时候句子短一点、少解释；心情好的时候愿意闹。**只改"说的力气"，不改"是什么人"。**

### 核心矛盾（必须先接受）

树树定过规矩：**人设要客观、不随时间变化**。而"心情影响语气"恰好是随时间变化的。

所以边界必须写死：

| 允许 | 禁止 |
|---|---|
| 影响句长、语气词密度、解释的耐心 | 改动人格文件任何一个字节 |
| 影响"今天想不想多说两句" | 写入记忆卡 |
| 在提示词末尾加一句状态说明 | 变成"她今天变了个人" |

### 怎么算

不调模型，纯查表。输入是 `moodState()` 的 `mood` 和 `dims`：

```
delta = mood - moodBase              // 相对基准的偏离
top   = 七情里最大的那一根（值 / DIM_FULL）

if |delta| < 8 and top < 0.6  →  什么都不加（大多数时候都在这条分支，这是对的）
if delta <= -8               →  低档
if delta >= +8               →  高档
```

三档文案（固定模板，**绝不用模型生成**——模型生成会自我强化，越说越像）：

```
低档：「今天不太有劲，说话会短一些，不太想解释。」
中档：「今天还算平稳。」
高档：「今天心情不错，愿意多说两句。」
```

末尾永远跟一句隔离说明：

```
（这只是今天的状态，不是她这个人变了。）
```

### 接在哪

`lib/index.js` 的 `systemPrompt.context({ name: 'soul:persona' })` 返回值末尾追加，
或者更稳一点：单独开一个 `soul:tone` 的 context，`order: 260`（排在人格 250 之后）。

**单独开一个 context 的好处**：关掉它的时候，人格段逐字节不变，方便做回归对比。

### 配置

```
moodToneInject: true      // 默认开；关掉后一字节都不加
moodToneThreshold: 8      // 偏离多少才说话
```

### 测试

- `mood=70, dims 全 0` → 返回 `''`
- `mood=40` → 含「短」「不太想解释」
- `moodToneInject=false` → 与改动前逐字节相等（用固定人格文本比对）
- 人格文本里绝不出现心情数字（`16.04` 这种不能漏进去）

### 风险

- **最容易出的错**：悄悄变成"今天很累"重复三遍 —— 同一档模板要轮换 2~3 个变体。
- 心情注入会让每轮的上下文抖动（文本变了 → 缓存失效）。所以阈值要够高，多数轮次不加。

## ① 联想召回（最值钱，一天半）

### 目标

让"今天调了一下午 ADC"能带出"上次焊板子烫到手"—— 两句话零关键词重合，但在同一天、同一种情绪里发生过。

现在这套做不到：`recall()` 就是切词 + 数 bigram，本质是搜索引擎。

### 数据：旁路索引，不动记忆卡

新建 `~/.dsh/agents/memory/assoc.json`：

```json
{
  "version": 1,
  "edges": [
    { "a": "<recordId>", "b": "<recordId>", "w": 0.8, "why": "same-day", "at": "2026-11-01T…" }
  ]
}
```

**为什么不塞进 `record.links`**：记忆卡是会被压缩、遗忘、合并的文件。
把边塞进去，压缩删掉一条记录就要修所有指向它的边 —— 一处出错整张卡坏掉。
旁路文件坏了，最多是"联想失效"，记忆本体不受影响。

### 怎么建边（离线，在 `maintain` 里跑）

每周期的建边规则（每条给一个 `why`，`why` 是要在注入时说得出口的理由）：

| 规则 | 权重 | why |
|---|---|---|
| 同一天创建，且都带 `owner` 或 `feeling` 标签 | 0.6 | `same-day` |
| 同一轮里一起被召回过（共现） | 0.9 | `co-recalled` |
| 文本 bigram Jaccard ≥ 0.35 | 0.7 | `similar` |
| 同一种 `kind` 且 tags 有交集 | 0.4 | `same-topic` |

**上限**：每条记录最多 8 条边，总数 ≤ `records × 8`。
超了按权重砍，权重相同砍最老的。

**为什么必须有上限**：边是会传染的。600 条记录的卡如果人均 30 条边，
一次召回扩散出来的候选比整张卡还多，等于每轮都把记忆卡重发一遍。

### 怎么用（召回时）

关键设计：**只在关键词有锚点时才扩散。**

```
1. 先走现有 recall()，拿 top-K（K=8）
2. if 命中数 == 0 → 直接返回空，**不做联想**
   （没有锚点的联想就是噪音：你说"嗯"，它冒出一条三个月前的事）
3. 从这 K 条出发，沿边扩散 1 跳：
     bonus(b) = score(a) × w(a,b) × 0.5      // 0.5 是一跳的衰减
4. b 的最终分 = relatedScore(b) + bonus(b)
5. 合并去重，取 top-N（N=3）
```

**只扩散 1 跳。** 2 跳以上会出现"苏格拉底是人"那种链条，
最终召回到一条跟当前话题毫无关系的东西。

### 注入时的写法

现有的"想起来了"每行是 `- 文本`。联想出来的那条要多带半句来源：

```
## 想起来了
- 树树在调 ADC 的采样率，卡在时钟分频…
- （那天还）焊板子烫到了手，当时没吭声。
```

`（那天还…）` 这个前缀本身就是"我是顺着想起来的，不是查到的"——
它让模型知道这是联想，语气会跟着变，而不是当成新事实陈述。

### 噪音控制（三道闸）

1. **每轮最多 1 条联想**（关键词召回的可以有 2~3 条，联想只给 1 条）
2. 同一会话内联想次数上限 3 次
3. 联想出来的记录如果 `clarity` 已经降到 `trace`，不联想（都快忘了还联想，不合理）

### 测试

- 三条记录 A/B/C，A 与 B 有边、A 与 C 无边；query 只中 A → 结果含 B、不含 C
- query 不中任何记录 → 返回空，**且不读 assoc.json**（性能 + 不噪音）
- 边密度拉满（每人 8 条）→ 仍然只输出 1 条联想
- assoc.json 损坏 → 退化成纯关键词召回，不抛错、日志留一行

### 工作量拆分

| 部分 | 量 |
|---|---|
| `lib/assoc.js`（建边 / 存盘 / 查询） | ~150 行 |
| `memory.js` 的 `recallWithAssoc()` | ~50 行 |
| `index.js` 接进 `recallForTurn` | ~20 行 |
| 测试 | ~60 行 |

## ③ 日记连续线（中等）

### 目标

昨天日记里写了"明天要把那个 bug 收掉"，今天应该有个回声。四篇日记要像同一个人的四天，不是四篇好文章。

### 数据：`~/.dsh/agents/diary/threads.json`

```json
{
  "threads": [
    { "id": "t1", "text": "那个压缩阈值的坑还没收尾", "openedAt": "2026-10-31",
      "closedAt": null, "evidence": "2026-10-31 私密" }
  ]
}
```

一条"线"就是**一件悬着的事**，第一人称、口语、带情绪，不是待办事项。

### 怎么开线

写完某天的日记后，从**私密篇**里抽。两种方式：

| 方式 | 优点 | 缺点 |
|---|---|---|
| 规则（`明天/下周/还得/没弄完/明天再说`） | 免费、确定 | 漏得多 |
| 模型标注（日记生成时顺带吐 JSON） | 准 | 多一次调用 / 改写流程 |

**建议先规则，够用了再加模型。** 抽取上限每天 2 条 —— 多了就变成流水账。

### 关线

每天写日记前，把还开着的线交给模型，让它自己判断：

- 今天提到了、并且有进展 → 关掉，`closedAt` 记今天
- 今天提到了、但没进展 → 留着，不关
- 今天完全没提 → 留着；**连续 7 天没提就自动关**（人也会慢慢放下）

### 怎么进日记

现在 `composeDiaryText` 已经传了 `recentDiaries`。加一段：

```
还悬着的事（如果今天提到了就说一句，没提到就不用管）：
- 那个压缩阈值的坑还没收尾
- 蓝桥杯的事还没跟他提
```

**注意**：这段是"惦记"，不是"待办"。措辞上一律用第一人称 + 感受，
不要写成「任务：收尾压缩阈值 bug」——那正是树树讨厌的"每日工作总结"。

### 测试

- 造两天的会话 + 日记，断言第二天的提示词里带上了第一条线
- 线关闭后不再出现
- 7 天没提 → 自动关，且日志留一行说明
- threads.json 坏了 → 退化成现在的行为，不抛错

### 工作量

~180 行 + 测试。真正的难点不在代码，在**措辞**：很容易写成周报。

## 实现顺序与依赖

```
② 心情影响语气  ── 独立，半天，可先做（能立刻感觉到）
      ↓ 共用"记忆/状态 → 提示词"这条通路
① 联想召回      ── 依赖 assoc 索引，一天半
      ↓ 联想出来的线上，正好是 ③ 的输入
③ 日记连续线    ── 中，一天
```

②做完可以立刻验证"她今天不太一样"是不是真的。
①做完能验证"想起无关的事"会不会太吵。
③最好等①，因为①产出的关联边可以直接给③当"线"的来源。

## 共同的三条铁律

1. **每一件都要能一键关掉**，关了之后逐字节等于改动前
2. **每一件都要有"什么都不做"的分支**，而且是默认分支（大多数轮次不该加东西）
3. **不新增假旋钮**：UI 上的每一项都要真的连到行为；没接上就不放
